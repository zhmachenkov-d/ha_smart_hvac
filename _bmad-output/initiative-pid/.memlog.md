- (decision) D1: Remove Outdoor Temperature / Weather Feedforward / CAP-7 entirely from SWT path; ADR 0004 superseded
- (decision) D2: Multi-zone PID uses weight-normalized averages of air temp and setpoint over Zones with Heating Demand only; max Zone Error is diagnostic/log only
- (decision) D3: Plant write remains via existing Home Assistant OpenTherm Set Water Temperature entity; no direct OT protocol stack
- (decision) D4: Ship fixed-gain PID first; RLS adaptive retune is a later epic, not mixed into the first closed loop
- (decision) D5: Keep Plant Management / Heating Demand gates: demand writes command; idle writes 0+clear; plant-off no write+clear
- (decision) D6: SWT = clamp(base_water_temp + u_pid) with base_water_temp from yaml; PID output is a correction not an absolute
- (decision) D7: Zone weight per Zone in apps.yaml; omitted weight defaults to 1.0; normalize over demand Zones
- (decision) D8: control_interval default 300s is the only path that advances PID state and writes SWT on demand; events may clear on idle/plant-off but must not write a new demand SWT
- (decision) D9: Round SWT to 0.1 C before write; skip plant command when rounded value equals last commanded
- (decision) D10: Use project setpoint_min/setpoint_max as sole SWT clamp; no separate Bosch 30-80 band in App code
- (decision) D11: Out of initiative scope: direct OT daemon, numpy demo process, Kd!=0, runtime weights outside yaml
- (requirement) R1: Under Plant Management on and Heating Demand, App commands SWT = round_0.1(clamp(base_water_temp + u_pid)) where u_pid is fixed-gain PID on weight-normalized demand-zone air vs setpoints
- (requirement) R2: Plant Management on and no Heating Demand writes 0 and clears PID ephemeral/water-path state; persisted files for later RLS (if any) untouched until that epic defines them
- (requirement) R3: Plant Management off does not write SWT and clears ephemeral/water-path state
- (requirement) R4: Outdoor Temperature, Weather Feedforward, CAP-7 rise-rate auto-correct, and ff_auto_correct_state.json are removed from the SWT path and commissioning; domain docs and a new ADR supersede ADR 0004
- (requirement) R5: Periodic control_interval (default 300s) is the only schedule that advances PID integral/state and issues a demand-path SWT write
- (requirement) R6: Event listeners may clear on idle/plant-off/fail paths immediately; they must not write a new demand SWT or advance PID state
- (requirement) R7: After 0.1 C rounding, equal to last commanded SWT skips the plant service call
- (requirement) R8: Multi-Zone Coordinator still owns Heating Demand; weighted averages for PID use only demand Zones; max Zone Error is not an SWT driver
- (requirement) R9: Later epic delivers RLS-based retune of PID gains without restoring weather feedforward
- (constraint) C1: SWT clamp uses existing setpoint_min/setpoint_max only
- (constraint) C2: Implementation stays inside AppDaemon ha_smart_hvac App writing the existing HA plant entity
- (constraint) C3: Fixed PID first; RLS not in the same ship as the first closed loop
- (constraint) C4: Derivative gain stays 0 for thermal noise; no direct OT/numpy daemon from the example
