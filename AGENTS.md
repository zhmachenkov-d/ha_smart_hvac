## ha_smart_hvac

AppDaemon Apps that control multi-zone OpenTherm HVAC through Home Assistant. Python 3.12, uv, AppDaemon 4.5.13. Domain language in `CONTEXT.md`; ADRs in `docs/adr/`; planning output in `_bmad-output/`.

## Policy

- Never push to `main`; PRs only.
- Never run `./scripts/run-appdaemon` while the Production AppDaemon add-on is up — Exclusive Session only (ADR 0001).
- Never commit `.env` or `appdaemon/secrets.yaml`. Edit `.env`; do not hand-edit `secrets.yaml` (regenerated by `./scripts/run-appdaemon`).
- Ask before changing house entity IDs in `apps/apps.yaml`.

## Where things are

- Domain terms and avoid-list: `CONTEXT.md`
- Architecture decisions: `docs/adr/` (0001 Exclusive Session, 0004 weather-curve SWT)
- App package: `apps/ha_smart_hvac/`; entity wiring: `apps/apps.yaml` (gitignored; start from `apps.yaml.example` at repo root)
- Algorithm depth / citations: `knowledge/`
- In-flight planning artifacts: `_bmad-output/`

## Running and verifying

- Use `uv run pytest` and `uv run ruff …` — bare `pytest` is not the project env.
- Requires Python 3.12 (`requires-python = ">=3.12,<3.13"`).
- Before local AppDaemon: Exclusive Session (stop Production add-on), then `./scripts/run-appdaemon`.
- CI installs with `uv sync --frozen --group dev` (stricter than a plain `uv sync --group dev`).

## Conventions that differ from defaults

- Plant Management off means no Set Water Temperature write and cleared ephemeral / water-path state — not “write 0”. Persisted `ff_auto_correct_state.json` is left untouched.
- Heating Demand idle writes 0 and clears ephemeral / water-path state; that path is only when Plant Management is on.
- Omitting `weather_feedforward.auto_correct` means CAP-7 rise-rate auto-correct is on (E2 defaults); there is no `enabled` switch.
